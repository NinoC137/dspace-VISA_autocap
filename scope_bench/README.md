# 示波器自动化台架（MXO38 / MSO58B）

本目录包含示波器选择、连接检查、采集、文件传输、截图和离线分析。具体主机地址、账号、盘符、挂载点和仪器身份信息由本地配置提供，不在仓库文档中记录。

## 按需拉取 Tek 内部 `.tss` 文件

在 `START_SCOPE_BENCH.cmd` 窗口中选用 **MSO58B**，确认没有正在运行的采集或截图后，点击 **拉取 Tek .tss**。

工具会递归查找仪器中的 `.tss`，读取历史清单和本地归档，按相对路径、文件大小和 SHA-256 判断是否可以复用。已存在且匹配的文件不会重复下载；新增或大小变化的文件会分块读取，完整读出并校验后立即写入独立的 `Tek-scope/run_*/` 目录。

每次操作生成 `transfer_manifest.json`，记录发现的文件以及新增、复用、失败项。旧清单缺少哈希时只能证明路径和大小匹配，不能证明仪器上的同名文件内容未变。仪器原文件不删除，失败时保留已完成文件，未完成的 `.part` 文件不视为成功副本。

拉取过程不启动 ControlDesk 批测，也不触发新的示波器采集。通信过程中不要强制关闭窗口；若链路中断，先等待当前操作结束，再按界面提示重试或恢复仪器连接。

实现位于 `scope_bench/tek_tss_transfer.py`，部署侧辅助脚本的源码镜像位于 `tools/tek_pull_tss.py`。锁、暂存区和最终结果目录都由配置项决定。

## 选择仪器与日常流程

1. 启动 `START_SCOPE_BENCH.cmd`，选择 MSO58B 或 MXO38。
2. 检查通道、单位、垂直量程、采样率、记录长度和触发条件。
3. 点击“检查连接”，确认 ControlDesk、示波器和结果目录状态。
4. 需要硬件运行时，由现场操作者确认电源和保护设置，再启动批测。
5. 批测结束后检查 `manifest.json`、`waveforms.h5`、截图、分析报告和 `screenshots.status`。

默认采集时长、通道选择、截图跨度和后端由 `bench_config.json` 控制。配置文件中的部署字段必须在目标环境重新核对；文档中的示例不构成现场接线、量程或保护设置。

## Tek CH1 中段波形与 FFT 图

`plot_hvdc_detail.py` 只读取已保存的 Tek `waveforms.h5`，从 CH1 电流中截取中段窗口，生成时域图、单边 FFT、PNG、SVG 和 `index.json`。它不读取 dSPACE MF4，不启动采集，不修改示波器。

已有结果可使用顶层 `PLOT_HVDC_DETAIL.cmd`，传入一个完整的 `batch_*` 目录。结果写入该批次的 `hvdc_detail/`。

这些窗口是记录中部的实测数据，不等价于仿真时间点；报告中应同时保留原始数据、采样设置、窗口范围和生成索引。

## MXO38 原生截图

MXO38 支持按配置生成多档 Zoom 截图。流程为一次采集冻结、工况关断、HDF5 导出、原生 PNG 截图和离线分析；截图不重新触发采集，不写 ControlDesk 参数，也不延长使能时间。

每个 capture 的 `screenshots/` 通常包含原始 PNG、带说明的副本、`index.html` 和 `index.json`。原图不覆盖；若截图失败，已完成的 HDF5 和分析结果仍保留，需单独查看 `screenshots.status`。

## 结果与安全边界

- 运行结果目录、通信暂存目录和锁文件均应由配置指定，并加入 `.gitignore`。
- 真实批测前先执行 `Plan` 和 `Check`；离线模拟通过不代表硬件链路已经验证。
- 停止操作应先关闭使能，再停止采集和清理工作进程；若无法确认设备已关断，由现场操作者执行硬件停机流程。
- 严禁把账号、地址、密钥、序列号、屏幕截图或完整测量数据写进 README、设计文档或 Git 提交。

### 故障处理

| 现象 | 处理 |
| --- | --- |
| 连接检查失败 | 检查本地配置、通信服务、仪器状态和结果目录权限；不要先启动批测。 |
| `.tss` 拉取中断 | 保留已完成文件，删除或隔离未完成的 `.part` 文件后重试；用清单和 SHA-256 复核。 |
| 结果目录不可写 | 更换配置中的结果目录或修复权限；不要把结果写入源码目录。 |
| 截图失败但采集完成 | 保留 HDF5 和分析结果，查看 `screenshots.status`，之后离线重试截图。 |
| 仪器被其他程序占用 | 关闭其他控制会话，等待锁释放，再执行连接检查。 |
